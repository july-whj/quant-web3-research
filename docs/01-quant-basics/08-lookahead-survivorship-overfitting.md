# 第八章：识别未来函数、幸存者偏差和过拟合

## 8.1 回测结果为什么会失真

前几章完成了一条最小策略链路：

```text
获取 BTC 数据
→ 编写双均线信号
→ 完成第一次回测
→ 加入手续费和滑点
```

到这一步，策略已经能生成资金曲线，也能和 BTC 买入持有比较。

但回测越接近完整流程，越容易让人放松警惕。

回测看起来是客观计算：数据输入，代码运行，结果输出。问题在于，代码不会判断假设是否合理。只要时间关系错了、样本选错了、参数调过头了，资金曲线就可能被系统性美化。

这章不继续优化收益。它专门处理三个会让回测失真的问题：

```text
未来函数
幸存者偏差
过拟合
```

它们的共同点是：都会让历史表现看起来比真实情况更好。

如果不识别这些问题，回测就会变成确认既有判断的工具。它呈现的不是策略能力，而是被高估的历史表现。

## 8.2 什么是未来函数

未来函数，是指回测在某个时间点使用了当时还不可能知道的信息。

可以这样理解：

```text
如果我在 2026-01-01 做交易决策，
却用了 2026-01-02 之后才知道的数据，
这就是未来函数。
```

它不一定真的是一个叫 `future()` 的函数。更多时候，它是时间关系写错了。

比如，某一天的收盘价，只有当天结束后才知道。如果策略在当天收盘前就用这个收盘价做出决策，并假设自己已经按这个价格成交，回测就使用了当时尚未出现的信息。

未来函数会让回测结果明显变好。因为策略等于提前知道了市场之后的走势。

实盘时没有这种能力。真实交易只能使用当时已经出现的信息。

## 8.3 最常见的未来函数：当前信号乘当前收益

这是初学者最容易写出的错误。

假设策略规则是：如果收盘价高于 MA20，就持有 BTC。

错误写法可能是：

```python
df["ma20"] = df["close"].rolling(20).mean()
df["signal"] = df["close"] > df["ma20"]

df["return"] = df["close"].pct_change(fill_method=None)
df["strategy_return_wrong"] = df["signal"] * df["return"]
```

这段代码的问题在于：

```text
signal 用了当天收盘价
return 也是当天从上一根 K 线到当天收盘的收益
```

也就是说，策略用当天收盘后才知道的信号，去获得当天已经发生完的收益。

正确处理方式，是让信号至少向后移动一期：

```python
df["position"] = df["signal"].shift(1).fillna(False)
df["strategy_return_correct"] = df["position"] * df["return"]
```

`signal` 表示当天收盘后看到的信息。

`position` 表示下一期实际持有的仓位。

这就是第三章和第五章反复强调 `shift(1)` 的原因。它不是形式上的代码习惯，而是在告诉回测：策略不能在信息出现之前交易。

## 8.4 对比错误版本与正确版本

可以用第 4 章保存的 BTC 数据做一次对比实验。

先读取数据：

```python
import pandas as pd

df = pd.read_csv(
    "data/btc_usdt_1d.csv",
    parse_dates=["timestamp"],
    index_col="timestamp",
)

df = df.sort_index()
```

计算 MA20 和每日收益：

```python
df["ma20"] = df["close"].rolling(20).mean()
df["signal"] = df["close"] > df["ma20"]
df["return"] = df["close"].pct_change(fill_method=None)
```

错误版本：

```python
df["strategy_return_wrong"] = (
    df["signal"] * df["return"]
)
```

正确版本：

```python
df["position"] = (
    df["signal"]
    .shift(1)
    .fillna(False)
)

df["strategy_return_correct"] = (
    df["position"] * df["return"]
)
```

比较两条资金曲线：

```python
initial_cash = 1000

df["equity_wrong"] = (
    initial_cash
    * (1 + df["strategy_return_wrong"].fillna(0)).cumprod()
)

df["equity_correct"] = (
    initial_cash
    * (1 + df["strategy_return_correct"].fillna(0)).cumprod()
)

wrong_return = df["equity_wrong"].iloc[-1] / initial_cash - 1
correct_return = df["equity_correct"].iloc[-1] / initial_cash - 1

print(f"错误版本收益率：{wrong_return:.2%}")
print(f"正确版本收益率：{correct_return:.2%}")
```

在很多数据区间里，错误版本的结果会明显更好。

这并不说明策略更强，而是因为它使用了当天结束后才知道的信息。

这个实验适合作为回测入门阶段的必做练习。只有把错误版本和正确版本放在同一张图里，才能直观看到时间错位会怎样放大回测结果。

## 8.5 未来函数的其他常见场景

未来函数不只出现在 `signal * return` 里。

### 使用未来最高价或最低价

例如：

```text
如果未来 5 天最高价上涨超过 10%，今天买入。
```

这条规则在回测里可能表现很好，因为它直接把未来 5 天的结果写进了条件。

真实交易时，今天不可能知道未来 5 天最高价。

### 用全样本统计量处理历史数据

比如，把整个回测区间的均值、标准差、最大值、最小值都算出来，再回填到过去每一天。

这在机器学习和因子研究里很常见。

如果 2024 年的信号使用了 2025 年才出现的数据来标准化，就发生了信息泄露。

scikit-learn 的文档把这类问题称为数据泄漏：模型构建时使用了预测时无法获得的信息，结果会让评估过于乐观。

### 忽略数据发布时间

有些数据虽然对应某一天，但发布时间晚于交易决策时间。

常见例子包括：

```text
财报数据
宏观数据
链上聚合指标
新闻情绪数据
交易所储备报告
```

如果一份指标在晚上 8 点才发布，策略却假设当天早上已经能使用它，也属于时间错位。

量化交易里，数据不仅要有日期，还要有“当时是否已经可获得”的判断。

## 8.6 如何检查未来函数

每一个信号都要回答四个问题：

```text
信息产生时间：这条数据什么时候真正出现？
信号生成时间：策略什么时候能计算出信号？
最早成交时间：信号出现后，最早能在哪个价格成交？
收益计算区间：策略持仓后，获得的是哪一段收益？
```

检查代码时，重点看这些位置：

| 检查点 | 风险 |
|---|---|
| `shift(-1)` | 可能直接使用未来数据 |
| 当前信号乘当前收益 | 可能提前获得当天收益 |
| 未来最高价、最低价 | 明显使用未来结果 |
| 全样本均值、标准差 | 可能把未来样本信息回填到过去 |
| 数据发布时间 | 指标日期和可用时间可能不一致 |

不是所有 `shift(-1)` 都一定错。比如计算“未来收益”作为研究标签时可以使用，但它不能直接作为当时的交易信号。

最稳的原则是：

> 交易信号只能使用当时已经知道的信息。

## 8.7 什么是幸存者偏差

幸存者偏差，是指只看留下来的样本，忽略已经消失、下架、退市或失败的样本。

在股票市场中，一个常见错误是：

```text
用今天还在指数里的股票，回测过去十年策略表现。
```

问题在于，今天还在指数里的公司，往往已经经过了一轮筛选。过去十年里退市、长期下跌、被剔除的公司没有进入样本。

回测看起来是在研究历史，其实使用的是“已经存续到今天”的名单。

结果通常会被高估。

因为失败样本没有被纳入统计。

## 8.8 Web3 中的幸存者偏差更常见

Web3 资产的死亡率很高。

很多代币会经历：

```text
上线
短暂活跃
流动性下降
交易所下架
项目停止更新
价格接近归零
```

如果只用今天仍然在主流交易所上市的币回测过去，样本天然偏好幸存者。

常见错误包括：

- 用今天市值前 100 的币，回测过去几年的表现。
- 只研究仍然在 Binance 或 OKX 上线的交易对。
- 只下载今天仍然存在的 DEX 池子。
- 忽略已经归零、跑路、下架或流动性枯竭的项目。
- 用当前热门赛道名单，回看过去行情。

这样做会让策略看起来更稳定。

但真实交易时，交易者并不知道哪些项目会活到今天。

## 8.9 如何减少幸存者偏差

完全消除幸存者偏差并不容易，尤其在 Web3 里。很多历史数据并不完整，交易所也不会总是保留已经下架交易对的完整数据。

但可以降低它的影响。

第一，尽量使用当时真实存在的资产列表。

如果回测 2023 年 1 月，就只能使用 2023 年 1 月已经上市、已经有流动性的资产。

第二，记录交易对上线和下架时间。

一个交易对在某一天还不存在，策略就不能在那一天交易它。

第三，不要用今天的 Top 100 回测过去。

今天的 Top 100 本身就是历史筛选结果，不能直接拿来代表过去的完整市场。

第四，对归零、下架和流动性消失的资产做处理。

不能因为数据难以获取，就直接删掉失败资产。失败资产被删除以后，回测结果会被系统性抬高。

第五，如果无法处理，要在回测报告中写明。

例如：

```text
本回测只使用当前仍在交易所上市的交易对，存在幸存者偏差。
```

明确写出偏差，比把问题隐藏在结果里更可靠。

## 8.10 什么是过拟合

过拟合，是指策略过度适应历史数据，以至于对未来数据失去适应能力。

可以这样理解：

```text
策略不是找到了可重复的市场规律，
而是过度记住了这段历史。
```

在回测中，过拟合通常发生在反复调参之后。

一开始用 MA20/MA60，结果不好。

于是改 MA10/MA30。

还不好，再改 MA7/MA47。

继续改，直到找到一组收益最高、回撤最低、曲线最平滑的参数。

这时要警惕：这组参数可能只是最适合当前这段历史数据。

换一段行情，它可能立刻失效。

## 8.11 双均线策略中的过拟合

本书目前使用 MA20/MA60，不是因为这组参数一定最优，而是因为它容易解释。

MA20 可以理解为中短期趋势，MA60 可以理解为更长周期趋势。

如果只是为了让当前 300 天样本表现最好，把参数改成 MA17/MA43，或者 MA13/MA89，就需要问：

```text
为什么是这两个数字？
它们有交易含义吗？
还是因为这组参数在这段历史上表现最好？
```

参数越精细，越容易过度适应历史。

如果一个策略必须依赖非常精确的参数才能盈利，比如 MA17/MA43 有效，而 MA16/MA42、MA18/MA44 都失效，那么它的稳定性就很可疑。

稳定的策略不一定在某个参数点最好，但在相邻参数上不应出现明显失效。

## 8.12 如何减少过拟合

过拟合不能完全避免，但可以减少。

### 参数要有解释

MA20/MA60 至少有可解释性：一个偏中短期，一个偏中长期。

如果参数只是因为回测结果最好，就要谨慎。

### 保留样本外数据

不要把所有历史数据都用来选参数。

可以把数据分成两段：

```text
训练区间：用于观察和选择参数
测试区间：用于检验参数是否还能工作
```

在训练区间表现好，不代表策略有效。它还需要在未参与调参的测试区间保持基本一致的表现。

### 看参数附近是否稳定

不要只看最优参数。

如果 MA20/MA60 表现不错，可以同时看看：

```text
MA15/MA50
MA20/MA60
MA25/MA70
MA30/MA90
```

如果只有一个参数点异常好，而周围参数都很差，就要怀疑它只是偶然结果。

### 用不同市场环境测试

策略至少要在几类行情里看一遍：

```text
上涨行情
下跌行情
横盘震荡行情
高波动行情
低波动行情
```

趋势策略在趋势行情里表现好，并不奇怪。真正要看的是它在震荡行情里会亏多少。

### 加入手续费和滑点

很多过拟合策略的利润很薄。没有成本时看起来尚可，加入手续费和滑点后可能立刻失效。

第七章已经说明，成本不是装饰项。它会改变策略结论。

## 8.13 三个陷阱的区别

未来函数、幸存者偏差和过拟合，经常同时出现在糟糕的回测里。但它们不是同一个问题。

| 问题 | 本质 | 常见后果 |
|---|---|---|
| 未来函数 | 使用当时不知道的信息 | 回测虚假变好，实盘无法复现 |
| 幸存者偏差 | 只看活下来的样本 | 忽略失败资产，收益被高估 |
| 过拟合 | 过度适配历史数据 | 换一段数据后表现变差 |

未来函数是时间错位。

幸存者偏差是样本错位。

过拟合是参数和规则过度适配历史。

判断一份回测是否可靠，要分别检查这三件事。

## 8.14 用第 5 至第 7 章策略做一次自查

现在回到我们的 BTC 双均线策略。

### 是否有未来函数

第五章已经用上一期和当前均线判断金叉、死叉，并把目标仓位向后移动一期。

第六章使用下一日开盘收益计算持仓后的收益。

这比“当天信号乘当天收益”更严谨。

但仍然要写清楚假设：

```text
信号生成：当天收盘后
成交假设：下一日开盘调整仓位
收益区间：从当天开盘到下一日开盘
```

### 是否有幸存者偏差

当前策略只交易 BTC，不做多币种选择。

因此，幸存者偏差暂时不明显。

但如果后面扩展成“从当前市值前 100 的币里选交易对象”，幸存者偏差就会变得严重。

### 是否有过拟合

目前只使用 MA20/MA60，没有在大量参数中挑最优。

过拟合风险暂时较低。

但如果后续不断试参数，并只保留表现最好的一组，就会出现过拟合风险。

### 是否计入成本

第七章已经加入手续费和滑点假设。

这让回测从无成本版本进一步接近真实交易。

但成本仍然是估算。真实交易还会受到盘口、下单金额和市场波动影响。

## 8.15 本章实践

本章实践目标：检查自己的回测是否存在明显失真。

建议完成以下步骤。

第一，检查第六章和第七章 notebook，确认没有使用当前信号乘当前收益。

第二，故意写一个错误版本：

```python
df["strategy_return_wrong"] = df["signal"] * df["return"]
```

把它和正确版本资金曲线画在一起。

第三，写下错误版本为什么不能用于实盘。

第四，尝试几组均线参数，但不要只保留最优结果。至少记录：

```text
MA10/MA30
MA20/MA60
MA30/MA90
```

第五，写一段回测风险说明：

```text
是否存在未来函数：
是否存在幸存者偏差：
是否存在过拟合风险：
成本是否已经计入：
哪些地方仍然是假设：
```

这段说明比单独展示资金曲线更重要。它要求研究者明确写出回测边界。

## 本章小结

回测结果不等于策略能力。它可能被未来函数、幸存者偏差和过拟合放大。

未来函数会让策略提前知道答案。最常见的错误是用当前信号乘当前收益。

幸存者偏差会让样本天然变好。Web3 中归零、下架、流动性枯竭的资产很多，如果只看今天仍然活着的资产，回测很容易被高估。

过拟合会让策略记住历史，而不是适应未来。参数越精细、规则越复杂，越要检查样本外表现。

从这一章开始，评价策略不能只问“收益多少”，还要问：

```text
有没有使用未来信息？
有没有删掉失败样本？
是不是只适合这段历史？
加入成本后还成立吗？
换一段行情还成立吗？
```

能回答这些问题，回测才开始接近研究，而不是单纯展示结果。
