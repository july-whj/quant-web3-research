# 第十章：账户、钱包、私钥和助记词

很多人第一次接触 Web3，会把钱包理解成“存币的软件”。

这个理解不准确。

在 Web3 中，资产记录在链上。钱包软件通常只是帮助用户管理密钥、查看地址、签名交易、连接应用。

如果把钱包当成“存钱的 App”，就容易犯两个错误：以为卸载钱包资产就没了，或者以为别人拿不到手机就拿不到资产。

真正控制资产的，不是钱包图标，而是私钥或助记词。

本章要把四个概念拆清楚：

```text
账户
地址
私钥
钱包
```

## 10.1 账户不等于钱包

在以太坊这类账户模型链上，账户是链上的实体。

账户可以持有资产，可以和合约交互，也可以出现在区块浏览器里。

以太坊账户主要分为两类：

```text
外部账户 EOA：由私钥控制，普通钱包地址通常属于这一类。
合约账户 Contract Account：由智能合约代码控制。
```

外部账户可以主动发起交易。用户在钱包里点击确认，本质上是用外部账户的私钥签名一笔交易。

合约账户本身没有私钥。它由代码控制。合约通常不会像普通用户一样主动发起外部交易，但在被调用后，可以在同一笔交易执行过程中调用其他合约。

钱包不是账户。

钱包是管理账户的工具或界面。它可以是浏览器插件、手机 App、硬件钱包，也可以是程序里的签名模块。

一个钱包可以管理多个账户。一个账户也可以被多个兼容钱包导入和管理。

## 10.2 地址是什么

地址是账户在链上的公开标识。

以太坊地址通常以 `0x` 开头，后面是一串十六进制字符。

地址可以公开。别人可以向这个地址转账，区块浏览器也可以查询这个地址的交易记录。

但地址公开不代表身份公开。

链上地址本身只是一串字符。它和真实身份之间没有天然绑定。问题在于，一旦某个地址和交易所提现记录、社交账号、域名、NFT 头像、公开募资或项目方钱包关联起来，地址背后的行为就可能被追踪。

对量化研究来说，地址是重要分析对象，但不能轻易把地址等同于“一个真实的人”。

一个真实用户可能有很多地址。一个地址也可能代表交易所热钱包、合约、多签钱包、机器人、跨链桥或项目方金库。

## 10.3 私钥是什么

私钥是控制外部账户的核心。

拥有私钥，就可以对交易签名。交易被网络接受后，地址中的资产可以被转出，合约也可以被调用。

私钥不能公开。

可以用一个简化关系理解：

```text
私钥 → 公钥 → 地址
```

这个过程是单向的。可以从私钥推出地址，但不能从地址反推出私钥。

私钥丢失，通常无法找回资产。私钥泄露，资产可能被转走。

这和传统互联网账号不同。传统平台通常可以找回密码、冻结账号、联系客服处理异常。链上账户没有统一客服。交易一旦被签名并成功上链，通常不能撤回。

## 10.4 助记词是什么

助记词通常是一组单词，常见形式是 12 个或 24 个英文单词。

它不是普通登录密码。

在很多钱包中，助记词用于恢复一组账户。更准确地说，助记词会被用来生成种子，再根据一定的派生路径生成多个私钥和地址。

可以先这样理解：

```text
助记词 → 种子 → 多个私钥 → 多个地址
```

因此，泄露助记词通常比泄露单个私钥更危险。

泄露单个私钥，可能只影响一个地址。

泄露助记词，可能影响由这组助记词派生出来的一批地址。

这里还有一个容易忽略的点：不同钱包可能使用不同派生路径。大多数主流钱包遵循常见标准，但恢复钱包时如果发现地址不一致，可能是派生路径、链类型或账户序号不同。

入门阶段不需要深入派生路径细节，但要知道：助记词不是“某一个地址的密码”，它更像一组地址的根。

## 10.5 钱包到底做了什么

钱包软件通常负责这些事情：

```text
创建或导入助记词
派生地址
显示资产余额
连接 DApp
构造交易
展示交易内容
请求用户签名
广播交易
管理网络和 RPC
```

钱包不会把资产“下载”到本地。

钱包看到的余额，来自链上状态、节点、RPC、区块浏览器或索引服务。

所以，换一个钱包软件，只要导入同一组助记词或私钥，仍然可以看到同一批地址和资产。

反过来，如果助记词已经泄露，即使换手机、换钱包软件、修改钱包 App 密码，也不能让原地址重新安全。正确做法通常是立刻把资产转移到新的安全地址。

## 10.6 钱包密码和助记词不是一回事

很多钱包会要求设置本地密码。

这个密码通常用于解锁钱包软件，或者加密本地保存的密钥文件。

它不是链上账户本身的密码。

如果钱包密码丢失，但助记词仍在，通常可以重新导入钱包。

如果助记词丢失，只剩钱包密码，换设备后可能无法恢复账户。

如果助记词泄露，钱包密码也无法保护链上资产。

所以，安全优先级大致是：

```text
助记词 / 私钥 > 钱包本地密码 > 钱包 App 本身
```

## 10.7 热钱包、冷钱包和硬件钱包

热钱包是联网环境中的钱包。浏览器插件钱包、手机钱包、程序自动签名钱包，都可以算热钱包。

热钱包方便，但攻击面更大。

冷钱包是私钥长期离线保存的钱包。硬件钱包通常被归入这一类。硬件钱包的价值在于：私钥不直接暴露在联网电脑或手机中，签名在设备内完成。

冷钱包也不是绝对安全。如果用户在钓鱼网站上确认了恶意交易，硬件钱包也可能签出危险授权。

因此，硬件钱包解决的是私钥暴露问题，不自动解决“你看不懂交易内容”的问题。

学习阶段建议至少准备三个地址层级：

```text
学习测试地址：用于测试网、小额实验、连接陌生 DApp。
日常小额地址：用于少量真实资金操作。
长期保管地址：不随意连接 DApp，不做高频交互。
```

不要用一个主钱包做所有事情。

## 10.8 签名不等于转账，但签名也可能危险

钱包弹窗时，用户经常会看到“签名”。

签名可以分为几类。

第一类是链上交易签名。

这类签名会生成一笔交易，交易上链后可能转移资产、调用合约、消耗 Gas。

第二类是消息签名。

这类签名不一定直接上链，常用于登录 DApp、证明地址所有权、确认某些链下协议内容。

第三类是授权类签名。

有些签名不会立即转走资产，但可能授权某个合约或订单系统在未来使用资产。例如 Token 授权、permit 签名、挂单签名等。

所以，不能简单认为“只要不是转账就安全”。

每次签名前，至少确认：

```text
当前连接的是哪个网站？
当前是哪条链？
签名对象是谁？
是否会发起链上交易？
是否会消耗 Gas？
是否在授权 Token？
授权额度是多少？
签名内容是否能读懂？
```

看不懂的签名，不要确认。

## 10.9 授权为什么危险

在 DEX 交易中，用户经常需要先授权某个合约使用自己的 Token。

比如用户要用 USDT 换 ETH，钱包地址中的 USDT 合约需要允许 DEX 路由合约转走一定额度的 USDT。没有授权，路由合约不能完成兑换。

授权本身不一定立刻造成损失。

风险在于：

```text
授权给了假合约
授权额度过大
授权长期不撤销
授权合约存在漏洞
用户连接钓鱼网站后签了危险交易
```

很多钱包会提供无限授权选项。它方便后续交易，但会扩大风险。

学习阶段更建议用小额度授权，并定期检查和撤销不再需要的授权。

## 10.10 和量化交易的关系

做 Web3 量化交易时，钱包和私钥不是“登录问题”，而是系统安全问题。

只读研究阶段，不需要私钥。

例如读取区块、交易、事件日志、DEX 池子储备，都可以通过公开 RPC、区块浏览器或索引服务完成。

一旦进入自动化下单，程序就可能需要签名交易。这时风险会明显上升。

自动化交易至少要考虑：

```text
私钥如何保存
程序是否只能使用小额资金
是否有每日最大损失限制
是否限制可调用合约白名单
是否限制授权额度
是否能及时撤销异常授权
日志中是否会泄露密钥
服务器是否安全
```

本书在入门阶段坚持先做公开数据、回测和模拟盘，就是为了避免读者在没有安全框架时把私钥接入程序。

## 10.11 学习阶段的最低安全规则

学习阶段至少遵守这些规则：

- 笔记里只记录公开地址，不记录助记词和私钥。
- 不把助记词截图。
- 不把助记词发到聊天工具、邮箱、网盘或代码仓库。
- 不在陌生网页输入助记词。
- 不用主钱包连接不熟悉的 DApp。
- 不随意给合约无限授权。
- 测试钱包、日常钱包和长期保管钱包分开。
- 先在测试网或小额资金中验证流程。
- 程序化交易前，先完成只读数据实验和模拟盘。

这些规则不复杂，但执行不好，后面的策略研究没有意义。

## 本章实践

创建或整理一个专门用于学习的钱包，记录以下内容：

```text
钱包用途：学习测试
是否存放大额资产：否
公开地址：
使用网络：
是否和主钱包隔离：
助记词是否离线保存：
是否连接过陌生 DApp：
是否存在历史授权：
是否需要撤销无用授权：
```

注意：笔记中只能记录公开地址。不要记录助记词、私钥、钱包密码或密钥文件路径。

## 本章小结

账户是链上的实体，钱包是管理账户和签名交易的工具。

地址可以公开，私钥和助记词不能公开。助记词通常可以恢复一组地址，泄露后影响范围更大。

签名不等于转账，但签名也可能带来授权和资产风险。

对 Web3 量化交易来说，私钥管理是安全系统的一部分。只读研究不需要私钥；自动化执行必须把密钥隔离、授权限制和风险控制放在策略之前。
