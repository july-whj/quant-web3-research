# 第二部分：Web3 基础大纲

第一部分已经完成了交易、回测、手续费、滑点、资金曲线和回测陷阱。

第二部分开始补齐 Web3 基础。

这部分不是本书最终重点，但不能过于简略。后面要研究链上数据、DEX、Gas、资金池、跨链和安全风险，如果这里概念不准，后面很容易把数据解释错。

本部分的目标不是让读者成为区块链底层工程师，而是建立一套够用、准确、能继续扩展的基础模型。

## 本部分学习目标

读者完成第二部分后，至少应该能回答这些问题：

```text
区块链为什么不能只理解成“公共账本”？
区块、交易、事件日志和状态变化是什么关系？
交易哈希出现了，是否代表交易成功？
确认数和最终性有什么区别？
账户、地址、钱包、私钥、助记词分别是什么？
BTC、ETH、稳定币、ERC-20 Token 和封装资产有什么区别？
CEX 和 DEX 的成交机制为什么不同？
同一个地址在不同链上为什么不是同一份资产？
Chain ID 为什么必须进入数据表？
Gas 为什么会改变策略收益？
RPC、节点、智能合约和区块浏览器是什么关系？
预言机、跨链桥、授权、假 Token、低流动性和 MEV 为什么是风险来源？
```

第二部分结束后，读者应该能够打开区块浏览器，看懂一笔交易的大部分关键字段，并知道哪些字段后续会进入量化数据表。

## 第 9 章：区块链、区块、交易与共识

本章建立链上数据的底层语言。

重点不再停留在“区块链是公开账本”这个比喻，而是说明区块链更准确地说是一套由节点共同维护的、有顺序的、可验证的状态记录系统。

本章核心内容：

- 公共账本比喻的边界。
- 比特币 UTXO 账本和以太坊状态机的差异。
- 区块、区块高度、区块哈希、父区块哈希和区块时间。
- 交易是签名后的状态变更请求。
- `from`、`to`、`input data`、`nonce`、`status`、`gas used` 等字段。
- 交易从签名到上链的完整流程。
- pending、确认数、最终性和区块重组。
- PoW、PoS、PoA 与完整共识机制的关系。
- 链上数据和交易所数据的差异。

本章完成后，读者应该知道：链上数据不是一出现就绝对稳定，交易哈希也不等于交易成功。

## 第 10 章：账户、钱包、私钥和助记词

本章解决 Web3 使用中最容易误解的部分：钱包和账户。

本章核心内容：

- 账户不等于钱包。
- 外部账户 EOA 和合约账户的区别。
- 地址可以公开，但不能轻易等同于真实用户。
- 私钥、公钥、地址之间的关系。
- 助记词、种子、派生路径和多个地址之间的关系。
- 钱包软件真正负责的事情。
- 钱包密码和助记词不是一回事。
- 热钱包、冷钱包、硬件钱包和测试钱包。
- 签名不等于转账，但签名也可能危险。
- Token 授权为什么是重要风险点。
- 自动化交易中的私钥管理边界。

本章完成后，读者应该知道：资产不在钱包软件里，真正控制资产的是私钥或助记词。

## 第 11 章：BTC、ETH、稳定币与 Token 标准

本章把常见 Web3 资产分清楚。

本章核心内容：

- 原生资产和智能合约 Token 的区别。
- BTC 主网资产、CEX 账户 BTC 和封装 BTC 的区别。
- ETH 既是交易资产，也是 Gas 资产。
- 稳定币的作用和风险。
- 同一稳定币在多条链上的不同版本。
- ERC-20 的 `balanceOf`、`transfer`、`approve`、`allowance`、`transferFrom`。
- decimals、symbol 和合约地址。
- ERC-721、ERC-1155 的基础定位。
- Wrapped Token 和跨链资产的风险。
- 数据表中为什么不能只记录 symbol。

本章完成后，读者应该能区分原生币、稳定币、ERC-20 Token、NFT、封装资产和交易所余额。

## 第 12 章：中心化交易所 CEX 与去中心化交易所 DEX

本章比较两类交易场所。

本章核心内容：

- CEX 的账户体系、托管、订单簿和撮合。
- CEX 行情数据的优点和边界。
- DEX 的钱包交互、合约执行和链上记录。
- AMM、资金池和 `x * y = k`。
- 集中流动性为什么让池子分析更复杂。
- DEX 聚合器和多跳路径。
- CEX 与 DEX 在账户、成本、透明度、失败成本和风险上的差异。
- 为什么价格差不等于套利机会。
- DEX 数据为什么不能只看交易 `to` 地址。

本章完成后，读者应该理解：CEX 和 DEX 不是同一种市场结构，不能直接用同一套数据处理方式。

## 第 13 章：公链、Chain ID、Gas 与区块确认

本章处理多链环境和链上成本。

本章核心内容：

- 公链、主网、测试网和 Layer 2。
- Chain ID 的作用。
- 同一个地址在不同链上为什么不是同一份资产。
- Gas、Gas Limit、Gas Used、base fee、priority fee。
- 失败交易为什么也可能扣 Gas。
- 确认数和最终性的区别。
- Gas 对低资金量策略的影响。
- 链上数据表中为什么要记录 `chain_id`、`gas_used`、`fee_native`。

本章完成后，读者应该知道：链、Gas 和确认不是背景信息，而是策略成本和数据质量的一部分。

## 第 14 章：智能合约、RPC、节点与区块浏览器

本章讲清楚链上数据的读取路径。

本章核心内容：

- 智能合约是部署在链上的程序。
- 合约地址和普通地址的差异。
- 只读调用和写入交易。
- ABI 是合约接口说明。
- `input data` 和函数选择器。
- 事件日志是链上数据分析的重要来源。
- 节点、全节点、归档节点和第三方节点服务。
- RPC 是程序访问节点的入口。
- 区块浏览器是展示和索引工具，不是链本身。
- 直接 RPC 和索引服务的取舍。
- 交易回执为什么重要。

本章完成后，读者应该能理解：Python 读取链上数据，本质上是在通过 RPC 或索引服务读取区块、交易、回执、事件日志和合约状态。

## 第 15 章：预言机、跨链桥与链上安全风险

本章进入 Web3 风险识别。

本章核心内容：

- 智能合约不能直接知道链下世界。
- 预言机如何把链下数据带到链上。
- 预言机价格不是可成交价格。
- 跨链桥的常见模式。
- 跨链桥风险和跨链执行风险。
- Token 授权风险。
- 假 Token 和钓鱼链接。
- 流动性风险。
- MEV 与交易排序风险。
- 合约权限、可升级、多签和暂停功能。
- 为每个 Token、协议和策略建立风险记录表。

本章完成后，读者应该建立一个底线：链上策略不能只看价格优势，还要同时看成本、执行和安全风险。

## 第二部分完成标准

完成第二部分后，读者应该能做到：

- 解释区块、交易、事件日志、状态变化和共识的关系。
- 读取一笔链上交易，并判断它是否成功。
- 区分交易哈希、交易状态、交易回执和事件日志。
- 区分账户、地址、钱包、私钥和助记词。
- 说明为什么助记词不能写入笔记、截图或上传网盘。
- 区分 BTC、ETH、稳定币、ERC-20 Token、NFT、封装资产。
- 说明为什么 Token 数据必须记录链、合约地址和 decimals。
- 解释 CEX 与 DEX 在市场结构上的差异。
- 说明 Gas 为什么会影响策略收益。
- 知道 Chain ID 为什么必须进入多链数据表。
- 理解智能合约、RPC、节点、区块浏览器和索引服务的关系。
- 识别预言机、跨链桥、授权、低流动性、MEV 和钓鱼链接等基础风险。

第二部分结束后，第三部分才开始进入真正的链上数据实践。
