# 第十五章：预言机、跨链桥与链上安全风险

Web3 交易的风险不只来自价格波动。

传统交易里，交易者主要关注价格、成交量、流动性、手续费和交易所风险。

链上交易还要关注合约、授权、预言机、跨链桥、Gas、MEV、钓鱼链接、假 Token 和区块确认。

这些风险如果不进入研究框架，策略回测可能看起来有收益，真实执行时却无法承受。

本章是第二部分的收束章节。目标不是让读者变成安全审计专家，而是建立基础风险识别能力。

## 15.1 智能合约不能直接知道链下世界

智能合约运行在链上。

它可以读取链上状态，例如账户余额、合约变量、事件日志。

但它不能直接知道链下世界发生了什么。

例如：

```text
ETH/USD 价格是多少？
某个中心化交易所最新成交价是多少？
某场比赛结果是什么？
某个现实资产是否完成交割？
某家公司财报数据是多少？
```

这些信息不在链上。

如果合约需要使用链下数据，就需要某种机制把数据带到链上。

这就是预言机的作用。

## 15.2 预言机是什么

预言机是把外部数据提供给链上合约的机制。

最常见的是价格预言机。

借贷协议需要价格来判断抵押品是否足够。

衍生品协议需要价格来结算盈亏。

稳定币协议可能需要价格来判断抵押率。

预言机通常不是简单地把某一个交易所价格搬到链上。它可能聚合多个数据源，经过过滤、加权、延迟、异常处理后再更新到链上。

因此，预言机价格不是“市场真相”，而是按照特定规则生成的链上可用价格。

## 15.3 预言机风险

预言机会引入新的风险。

常见风险包括：

```text
数据源异常
价格更新延迟
低流动性市场被操纵
报价精度不足
异常价格没有及时过滤
合约读取了错误价格源
预言机停止更新
```

如果借贷协议读取错误价格，可能触发错误清算。

如果量化策略把预言机价格当成真实成交价格，可能高估套利空间。

研究预言机相关数据时，至少要记录：

```text
价格来源
更新频率
更新时间
价格精度
是否有心跳机制
是否有偏离阈值
和 CEX / DEX 可成交价格的差异
```

预言机价格适合做参考，不应直接等同于可成交价格。

## 15.4 跨链桥是什么

不同区块链之间不能天然共享状态。

如果用户想把资产从一条链转移到另一条链，通常需要跨链桥。

常见跨链方式包括：

```text
源链锁定资产，目标链铸造映射资产。
源链销毁资产，目标链释放资产。
通过消息协议让不同链上的合约互相通信。
通过流动性池在不同链之间兑换资产。
```

用户看到的是“跨链转账”。

实际背后可能包含锁仓、消息验证、签名、多签、目标链铸造、流动性兑换、延迟确认等多个环节。

每多一个环节，就多一层风险。

## 15.5 跨链桥风险

跨链桥是 Web3 中风险较高的基础设施之一。

主要风险包括：

```text
桥合约漏洞
验证者或多签风险
消息验证失败
目标链流动性不足
到账延迟
跨链资产脱锚
假桥网站
桥服务暂停
```

对量化交易来说，跨链桥还带来执行风险。

如果策略依赖跨链搬运资金，就要计算：

```text
源链 Gas
目标链 Gas
桥费用
跨链等待时间
到账不确定性
等待期间价格变化
目标链可用流动性
桥是否限额或暂停
```

只看到两条链之间有价差，不代表可以套利。

如果跨链时间太长，价格差可能在到账前消失。

如果目标链流动性不足，资产到了也可能卖不掉。

## 15.6 Token 授权风险

Token 授权是 Web3 中最常见，也最容易被低估的风险之一。

在 DEX 交易中，用户经常需要先授权某个合约使用自己的 Token。

授权额度可以很小，也可以很大。

很多 DApp 为了方便用户，会提示无限授权。

无限授权的好处是以后交易不必反复授权。

问题是，一旦授权对象有问题，或者用户授权给了假合约，资产风险会扩大。

检查授权时，要看清楚：

```text
授权的是哪个 Token？
授权给哪个合约？
授权额度是多少？
授权是否仍然需要？
合约是否可信？
是否可以撤销或降低额度？
```

学习阶段不建议用主钱包做高频授权。

## 15.7 假 Token 和钓鱼链接

任何人都可以部署 Token 合约。

这意味着假 Token 很常见。

攻击者可以创建和主流资产名称相似、符号相同、头像相似的 Token。

如果只看 symbol，很容易误判。

识别 Token 时，优先确认：

```text
所在链
合约地址
项目官网
区块浏览器认证信息
交易所充值页面
可信数据网站标记
流动性池真实深度
持有人分布
合约是否可疑
```

钓鱼链接也是常见风险。

攻击者会制作和真实 DApp 相似的网站，引导用户连接钱包、签名、授权或输入助记词。

只要网页要求输入助记词，基本就应该直接关闭。

## 15.8 流动性风险

链上资产显示价格，不代表能按这个价格成交。

如果资金池很浅，一笔交易就可能造成巨大滑点。

有些小币种 K 线看起来上涨很多，但池子里真实可卖出的流动性很少。买得进去，不一定卖得出来。

分析 DEX 资产时，要看：

```text
池子总流动性
当前价格附近流动性
买入滑点
卖出滑点
交易路径
价格影响
LP 是否集中
是否存在撤池风险
```

只看价格不看流动性，会把无法成交的机会当成收益。

## 15.9 MEV 与交易排序风险

MEV 指链上交易排序带来的额外价值。

入门阶段不需要深入 MEV 算法，但要知道它会影响 DEX 交易。

常见场景包括：

```text
抢跑
三明治攻击
清算竞争
套利排序
```

如果用户提交一笔大额 DEX 交易，且滑点设置较宽，其他参与者可能在交易前后插入交易，使用户成交价格变差。

这也是链上交易和 CEX 交易的差异之一。

在 CEX 中，用户主要面对撮合系统和订单簿。

在链上，交易进入区块前，排序和打包过程本身也会影响结果。

## 15.10 合约风险

智能合约一旦部署，不代表它永远安全。

常见合约风险包括：

```text
代码漏洞
权限过大
可升级代理风险
管理员私钥风险
多签成员风险
暂停功能风险
价格计算错误
重入攻击
整数精度问题
```

入门阶段不要求读者审计代码，但要会做基本判断：

```text
合约是否开源验证？
是否有审计报告？
是否可升级？
管理员权限有哪些？
是否有暂停交易功能？
资金是否集中在少数地址？
是否依赖外部合约？
```

这些问题不能保证安全，但能过滤掉一部分明显高风险项目。

## 15.11 对 Web3 量化研究的要求

从本章开始，评价链上策略至少要同时回答四个问题：

```text
价格是否有优势？
成本是否算完整？
执行是否可完成？
安全风险是否可承受？
```

如果一套策略只在价格上有优势，但需要经过高风险跨链桥、大额授权、低流动性池和不稳定预言机，就不适合入门阶段执行。

本书后续仍然坚持一个原则：

```text
先做只读数据研究
再做回测和模拟盘
最后才考虑小额、受控的执行实验
```

这个顺序不是保守，而是必要的工程流程。

## 15.12 建立风险记录表

以后每研究一个 Token、协议或策略，都应该建立风险记录。

基础字段可以包括：

```text
项目名称
所在链
合约地址
是否开源验证
是否可升级
管理员权限
是否依赖预言机
是否依赖跨链桥
是否需要 Token 授权
主要流动性池
池子深度
是否有历史安全事件
是否适合真实资金
```

风险记录不是形式。

它能防止研究者只看收益曲线，而忽略执行中的真实损失来源。

## 本章实践

选择一个你熟悉的 Token 或协议，做一次安全记录：

```text
项目名称：
所在链：
合约地址：
是否已验证源码：
是否可升级：
管理员权限是否清楚：
是否需要授权：
授权对象：
是否依赖预言机：
是否依赖跨链桥：
主要流动性在哪个池子：
池子深度是否足够：
最大风险是什么：
是否适合真实资金操作：
```

如果答案不清楚，就先标记为“不适合真实资金操作”。

这不是否定项目，而是承认自己当前信息不足。

## 本章小结

预言机把链下数据带到链上，但有延迟、数据源、更新频率和操纵风险。

跨链桥连接不同链，但引入合约、验证、流动性和到账风险。

Token 授权、假 Token、钓鱼链接、低流动性、MEV 和合约权限，都会影响真实交易结果。

第二部分到这里完成。读者现在应该能看懂一笔链上交易的大部分字段，也能理解钱包、Gas、Token、合约、RPC、预言机和跨链桥这些基础概念。

下一部分将进入 Web3 量化实践：获取链上数据，分析交易、事件日志、资金流和 DEX 池子。
