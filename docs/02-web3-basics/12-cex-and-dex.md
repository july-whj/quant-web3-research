# 第十二章：中心化交易所 CEX 与去中心化交易所 DEX

同样是买入 ETH，在 CEX 和 DEX 上发生的事情完全不同。

在 CEX 上，用户面对的是交易所账户、订单簿、撮合系统和内部账本。

在 DEX 上，用户面对的是钱包、智能合约、资金池、Gas、滑点和链上确认。

如果只看最后得到的资产数量，二者似乎差不多。做量化研究时，这种简化会出问题。

本章把 CEX 和 DEX 的结构差异讲清楚。

## 12.1 CEX 是什么

CEX 是中心化交易所。

用户在交易所注册账户，完成身份认证或安全设置，把资产充值到交易所，然后在交易所内部买卖。

用户看到的余额，是交易所账户系统里的余额。

资产充值到交易所后，链上通常只显示一笔转入交易。用户在交易所内部买入、卖出、挂单、撤单，大多数情况下不会逐笔反映到链上。

交易所内部有自己的撮合系统和账本。

这带来几个特点：

```text
交易速度快
订单类型丰富
行情数据结构清晰
API 容易使用
用户不直接控制交易所内资产
交易所内部细节不完全公开
```

第一部分使用的 BTC/USDT K 线，就属于典型 CEX 行情数据。

## 12.2 CEX 的订单簿和撮合

多数 CEX 现货交易使用订单簿。

订单簿记录买卖双方的挂单。

买盘表示愿意以某个价格买入，卖盘表示愿意以某个价格卖出。撮合系统按照交易所规则完成成交，常见规则是价格优先、时间优先。

订单簿中常见数据包括：

```text
买一价
卖一价
买卖价差
每档挂单数量
订单簿深度
最新成交价
成交量
```

CEX 对量化交易友好的地方在于数据稳定、接口标准化程度较高、回测容易入门。

但 CEX 数据也有边界。

交易所可能发生维护、限流、插针、异常成交、接口延迟、下单限制、提现暂停。交易所内部钱包调拨、真实库存、风控规则，外部用户无法完全看到。

所以，CEX 不是“没有链上风险”，而是风险转移到了平台、托管和撮合系统。

## 12.3 DEX 是什么

DEX 是去中心化交易所。

它不是一个单一模式。DEX 可以是 AMM、链上订单簿、聚合器、RFQ 系统，也可以混合多种机制。

入门阶段最常见的是 AMM 类型的 DEX，例如 Uniswap 这类协议。

在 DEX 上，用户通常不把资产充值到交易所账户，而是用钱包直接和智能合约交互。

交易过程大致是：

```text
用户连接钱包
选择交易资产和数量
如果需要，先授权 Token
钱包签名交易
交易提交到链上
合约执行兑换
交易成功后余额变化
```

DEX 交易会产生链上记录。任何人都可以查看交易哈希、区块、调用合约、事件日志和 Gas 成本。

透明不等于简单。DEX 交易需要处理链上执行风险。

## 12.4 AMM 与资金池

AMM 是自动做市商。

传统订单簿依赖买卖双方挂单。AMM 依赖资金池。

以 ETH/USDC 池子为例，池子里同时有 ETH 和 USDC。用户用 USDC 买 ETH，本质上是把 USDC 放入池子，并从池子取出 ETH。

经典恒定乘积模型可以简化为：

```text
x * y = k
```

`x` 和 `y` 是池子中两种资产的储备量，`k` 是乘积。

交易改变池子储备，价格随之变化。

如果池子很深，一笔小交易对价格影响不大。

如果池子很浅，一笔稍大的交易就会明显改变价格。

这就是价格冲击。

DEX 交易中的滑点和价格冲击，往往不是系统错误，而是交易规模相对池子深度过大。

## 12.5 集中流动性让问题更复杂

早期 AMM 可以用简单的 `x * y = k` 理解。

但现在很多主流 DEX 已经使用集中流动性。

集中流动性的意思是，流动性提供者可以把资金放在某个价格区间，而不是覆盖所有价格。

这会提高资金效率，但也让价格影响和流动性分布更复杂。

同样显示“池子 TVL 很高”，不代表当前价格附近有足够流动性。

对量化研究来说，不能只看总锁仓量。还要看当前价格附近的可用流动性、交易路径和实际报价。

## 12.6 DEX 聚合器是什么

DEX 聚合器会从多个池子、多个协议中寻找交易路径。

用户看到的是一次兑换，背后可能拆成多段路径：

```text
USDC → WETH
WETH → 目标 Token
或者一笔订单被拆到多个池子成交
```

聚合器可以改善报价，但也增加了解析难度。

在区块浏览器里，一笔交易可能调用聚合器合约，聚合器再调用多个 DEX 合约，最后产生多组事件日志。

做链上数据分析时，如果只看交易的 `to` 地址，可能只看到聚合器，看不到真正发生兑换的池子。

## 12.7 CEX 和 DEX 的主要差异

可以用表格对比：

| 维度 | CEX | DEX |
|---|---|---|
| 账户方式 | 交易所账户 | 链上钱包 |
| 资产控制 | 交易所托管 | 用户自托管 |
| 成交机制 | 订单簿撮合为主 | AMM、聚合器、链上订单簿等 |
| 数据来源 | 交易所 API | 区块、交易、事件日志、索引服务 |
| 成本 | 手续费、价差、提现费 | Gas、协议费、滑点、MEV |
| 透明度 | 内部撮合不完全公开 | 链上记录公开，但需要解析 |
| 失败成本 | 下单失败通常不消耗链上费用 | 失败交易可能消耗 Gas |
| 风险 | 托管、平台、风控、接口 | 合约、授权、流动性、排序 |

两者没有绝对好坏。

CEX 适合行情回测、订单簿研究、较高频的数据分析。

DEX 适合研究链上流动性、资金池价格、真实合约交互、稳定币偏离、跨市场价差和协议行为。

## 12.8 同一个价格，不一定是同一个市场

交易者经常说“ETH 价格”。

但不同市场里的 ETH 价格并不完全相同：

```text
CEX 上的 ETH/USDT
CEX 上的 ETH/USD
DEX 上的 WETH/USDC 池
Layer 2 上的 ETH/USDC 池
永续合约市场中的 ETH 标记价格
预言机中的 ETH/USD 报价
```

这些价格会相互影响，但它们不是同一个数据源。

市场波动剧烈、链上拥堵、流动性不足、交易所暂停提现时，价格差异可能扩大。

价格差不等于套利机会。

套利需要同时满足：

```text
两边都能成交
成本计算完整
资金能移动
时间足够短
滑点可控
提现和充值可用
链上交易不会失败
风险可承受
```

缺少任何一项，价差都可能只是表面机会。

## 12.9 对量化交易的影响

如果策略只在 CEX 交易，研究重点通常是：

```text
K 线质量
成交量
订单簿深度
手续费等级
API 稳定性
下单规则
风控限制
充值提现状态
```

如果策略研究 DEX，研究重点会变成：

```text
资金池储备
当前价格附近流动性
交易路径
Gas 成本
协议费
滑点
授权风险
交易打包延迟
MEV 风险
合约是否可升级
```

这也是本书的学习顺序：先从 CEX 公开行情入手，学会回测和成本计算，再进入 DEX 和链上数据。

否则读者容易在还没理解收益率、回撤、滑点之前，就被合约、RPC、Gas、MEV 同时淹没。

## 12.10 常见误区

第一个误区，是把 DEX 等同于“没有中间人，所以一定更安全”。

DEX 减少了托管风险，但增加了私钥、授权、合约和链上执行风险。

第二个误区，是认为链上公开就等于容易分析。

链上数据确实公开，但交易路径、事件日志、内部调用、聚合器拆单都需要解析。

第三个误区，是把 CEX 价格和 DEX 价格直接相减。

如果不计入手续费、Gas、滑点、跨链成本和资金时间，价差没有意义。

第四个误区，是忽略失败交易。

DEX 交易失败也可能消耗 Gas。回测如果只保留成功交易，会低估成本。

## 本章小结

CEX 是交易所账户、订单簿、撮合系统和内部账本。

DEX 是钱包、智能合约、资金池、Gas 和链上确认。

CEX 数据适合入门回测，DEX 数据更接近链上真实资产流动，但解析难度更高。

在 Web3 量化中，价格不是唯一变量。成本、流动性、路径、确认时间、失败交易和安全风险，都必须进入研究框架。
