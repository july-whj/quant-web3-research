# 第十三章：公链、Chain ID、Gas 与区块确认

Web3 不是单链世界。

同一个钱包地址，可能同时出现在 Ethereum、BNB Chain、Polygon、Arbitrum、Optimism 等网络中。地址看起来一样，但资产、交易历史、合约状态和 Gas 规则可能完全不同。

很多链上事故不是因为用户不会交易，而是因为把链、资产和地址混在了一起。

本章解决三个基础问题：

```text
我在哪条链上？
这笔交易要付多少执行成本？
这笔交易是否已经足够稳定？
```

## 13.1 公链是什么

公链可以先理解为开放访问的区块链网络。

任何人都可以按照规则读取数据、提交交易、运行节点或验证交易。不同公链在技术实现和治理方式上会有很大差异，但对使用者来说，它们都是独立的链上环境。

常见公链包括：

```text
Bitcoin
Ethereum
BNB Chain
Polygon
Solana
```

每条链都有自己的区块、交易、账户模型、费用规则和生态应用。

在一条链上发生的交易，不会自动出现在另一条链上。

这句话很基础，但非常重要。

如果你的 USDT 在 Ethereum 上，它不会因为你切换钱包网络到 BNB Chain 就自动变成 BNB Chain 上的 USDT。

钱包切换网络，只是切换查看和交互的链。资产本身仍然在原链上。

## 13.2 主网、测试网和 Layer 2

主网是真实资产运行的网络。

主网上的交易会消耗真实费用，资产有真实市场价值，错误操作可能造成真实损失。

测试网用于开发、学习和测试。测试网资产通常没有真实市场价值，适合练习转账、合约调用、RPC 读取和区块浏览器查询。

Layer 2 是建立在主网之外的扩展网络。它通常提供更低费用和更高吞吐，再通过某种方式和主网发生结算、数据发布或安全关系。

可以先用这个框架理解：

```text
主网：真实资产、真实成本、真实风险。
测试网：学习和开发环境。
Layer 2：更低成本的扩展环境，但仍有独立规则和风险。
```

Layer 2 不是“便宜版主网”这么简单。不同 Layer 2 的提现时间、数据可用性、排序器机制、跨链桥和生态流动性都不同。

入门阶段不需要深入 Rollup 技术，但要知道：Layer 2 上的交易和主网交易不是同一件事。

## 13.3 Chain ID 是什么

Chain ID 是链的身份编号。

它用于标识当前交易属于哪条链，也用于防止同一笔签名交易在不同链上被重复使用。

从使用角度看，Chain ID 回答的是：

```text
这笔交易到底发往哪条链？
```

Ethereum 主网的 Chain ID 是 1。其他链也有自己的 Chain ID。

做程序化数据时，Chain ID 是基础字段。

只记录地址是不够的。

推荐记录方式：

```text
chain_name：Ethereum
chain_id：1
address：0x...
asset：USDC
contract_address：0x...
```

如果以后做多链监控，不加 Chain ID 会造成严重混淆。

## 13.4 同一个地址，不代表同一份资产

EVM 生态中，同一个私钥可以在多条 EVM 链上生成同一个地址。

例如同一个地址可以同时存在于：

```text
Ethereum
BNB Chain
Polygon
Arbitrum
Optimism
```

但每条链上的余额、交易历史和合约授权都是独立的。

一个地址在 Ethereum 上有 100 USDC，不代表它在 Polygon 上也有 100 USDC。

一个地址在 BNB Chain 上授权过某个合约，不代表它在 Ethereum 上也授权过同一个合约。

如果区块浏览器或钱包页面没有明确显示链，数据就没有完整上下文。

这也是为什么本书后续做链上数据表时，会把 `chain_id` 放进基础字段。

## 13.5 Gas 是什么

Gas 是链上执行操作所需计算和存储资源的计量单位。

用户发起交易时，需要为网络处理这笔交易支付费用。不同链费用机制不同，但核心逻辑相似：链上资源不是免费的。

在以太坊中，Gas 费用通常用 ETH 支付。

一笔交易的费用可以先简化理解为：

```text
交易费用 = Gas Used × 每单位 Gas 价格
```

EIP-1559 之后，以太坊费用结构中有 base fee 和 priority fee。

base fee 是协议根据网络拥堵情况调整的基础费用，会被销毁。

priority fee 可以理解为给验证者的小费，用来提高交易被打包的吸引力。

对入门读者来说，先掌握三点：

- 交易越复杂，通常消耗 Gas 越多。
- 网络越拥堵，每单位 Gas 价格通常越高。
- 失败交易也可能消耗 Gas。

## 13.6 Gas Limit、Gas Used 和交易费用

Gas Limit 是用户愿意为这笔交易最多消耗多少 Gas。

Gas Used 是实际执行时消耗了多少 Gas。

交易费用根据实际消耗和 Gas 价格计算。

如果 Gas Limit 设置过低，交易可能无法完成。

如果 Gas Limit 设置高于实际需要，未使用部分通常不会全部消耗掉。钱包会估算一个合理值，用户不必手动计算所有细节。

但有一种情况要特别注意：如果交易执行过程中耗尽 Gas，状态会回滚，但已经消耗的 Gas 可能不会退回。

这意味着，链上失败不是免费的。

对量化策略来说，失败交易成本必须计入。

## 13.7 为什么失败交易也可能扣 Gas

链上交易失败，不代表网络没有工作。

如果交易已经进入执行阶段，节点已经消耗计算资源。即使合约最后回滚，执行过程也消耗了 Gas。

常见失败原因包括：

```text
滑点设置过低
授权额度不足
余额不足
交易路径失效
价格在打包前变化
合约条件不满足
Gas Limit 设置不足
```

DEX 策略尤其要关注这个问题。

回测中如果只记录成功兑换，而忽略失败交易 Gas，结果会比真实执行更好。

## 13.8 区块确认数

确认数表示一笔交易被打包后，又有多少新区块接在它后面。

可以简化理解为：

```text
确认数 = 当前最新区块高度 - 交易所在区块高度 + 1
```

确认数越多，交易被短期重组影响的概率通常越低。

中心化交易所处理充值时，经常要求达到一定确认数后才入账。不同资产、不同链、不同交易所要求不同。

对量化研究来说，确认数影响数据使用时机。

如果策略监控链上大额转账，刚看到交易并不代表资金已经可用。

还要考虑：

```text
交易是否成功？
所在区块是否足够稳定？
目标交易所是否已经入账？
是否可能发生重组？
是否只是内部钱包调拨？
```

## 13.9 最终性和确认数不是一回事

确认数是观察区块深度的一种方式。

最终性是协议层面判断交易历史是否很难被改变的概念。

不同链最终性规则不同。

PoW 链通常更偏概率最终性。区块越深，被替代的概率越低。

PoS 链可能有更明确的 finalized 状态，但具体机制取决于协议设计。

对入门者来说，重要的是不要把“区块浏览器查到了”直接等同于“绝对最终”。

后续做实时链上监控时，通常要设计一个确认延迟。例如只处理距离最新区块若干个区块之前的数据。

这会牺牲一点实时性，换取更高的数据稳定性。

## 13.10 Gas 与低资金量策略

低资金量阶段，Gas 影响非常大。

假设一次链上买入需要 2 美元 Gas，一次卖出也需要 2 美元 Gas，再加上授权和滑点，总成本可能已经超过小额交易的预期利润。

这和第七章讨论的手续费、滑点是同一类问题：成本会改变策略结论。

链上策略至少要计入：

```text
授权 Gas
买入 Gas
卖出 Gas
失败交易 Gas
跨链 Gas
DEX 协议费
滑点
价格冲击
MEV 影响
```

如果一套策略在不计 Gas 时盈利，计入 Gas 后亏损，那么它不适合真实执行。

## 13.11 对数据表设计的影响

后续做链上数据分析时，建议每条记录至少包含：

```text
chain_id
chain_name
block_number
block_timestamp
transaction_hash
transaction_status
from_address
to_address
gas_used
fee_native
token_address
token_symbol
```

如果是 DEX 交易，还应记录：

```text
pool_address
router_address
input_token
output_token
amount_in
amount_out
price_impact
slippage
```

这些字段看起来繁琐，但它们能避免后续把不同链、不同资产、不同成本混在一起。

## 本章实践

找一笔链上交易，记录：

```text
链名称：
Chain ID：
交易哈希：

确认数：

Gas Used：
Gas 单价或费用字段：
最终交易费用：
费用使用的原生资产：
交易是否成功：
如果失败，是否仍消耗 Gas：
```

再写一句判断：

```text
如果把这笔交易放入策略回测，哪些成本需要计入？
```

## 本章小结

多链环境下，地址不是完整上下文。必须同时记录链和 Chain ID。

Gas 是链上执行成本。失败交易也可能消耗 Gas。确认数和最终性决定了链上数据什么时候可以被更安全地使用。

对 Web3 量化交易来说，链、Gas 和确认不是背景信息，而是成本模型和数据质量的一部分。
