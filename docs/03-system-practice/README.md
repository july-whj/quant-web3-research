# 第三部分：系统驱动的 Web3 量化实践大纲

第 16 章到第 23 章不再按知识点展开，而是围绕开源系统建设展开。

这一部分的写法要遵守一个原则：

```text
先定义系统模块，
再写代码实验，
最后把实验整理成书稿。
```

也就是说，章节内容必须来自系统，而不是为了写章节而找概念。

## 第三部分目标

第三部分完成后，项目应该从“书稿 + Notebook”升级为“最小开源研究系统”。

读者应该可以完成一条最小研究流程：

```text
获取数据
→ 清洗和标准化
→ 计算指标
→ 生成策略信号
→ 执行回测
→ 计算风险指标
→ 输出报告
→ 记录复盘
```

这条流程暂时只做研究、回测和模拟盘，不做真实资金自动交易。

## 第 16 章：开源系统的整体架构与目录设计

系统模块：

```text
项目结构

数据目录
源码目录
示例目录
测试目录
文档目录
```

本章要解决的问题：

- 为什么从第 16 章开始不再只写 Notebook。
- 为什么要把数据、策略、回测、指标、报告拆成模块。
- 开源项目目录如何设计。
- 哪些内容放在 `docs/`，哪些放在 `src/`，哪些放在 `examples/`。
- 为什么配置文件不能保存密钥。

最小实验：

```text
创建项目目录骨架。
把现有 metrics.py 整理为可复用模块。
新增一个 examples/backtest_ma_cross.py 作为命令行示例。
```

本章输出：

```text

最小运行命令
```

## 第三部分完成标准

第三部分完成后，项目至少应该具备：

- 一个清晰的开源项目目录。
- 一个可运行的 CEX 行情数据获取示例。
- 一个可运行的链上交易读取示例。
- 一个指标计算模块。
- 一个配置化策略模块。
- 一个回测引擎。
- 一个回测报告输出。
- 一个最小模拟盘。
- 一个风险检查模块。
- 一个开源 README 初稿。

此时项目可以发布 V0.2。

## 当前开发顺序

建议按这个顺序推进：

```text
第 16 章：先整理目录和 README
第 17 章：整理 CEX 数据模块
第 19 章：整理指标模块
第 20 章：整理策略模块
第 21 章：整理回测模块
第 23 章：生成回测报告和开源发布清单
第 18 章：补链上数据模块
第 22 章：补模拟盘
```

原因很简单：当前已有 BTC 行情、指标、策略和回测 Notebook，先把已有内容系统化，成本最低。
