# 第三部分：系统驱动的 Web3 量化实践大纲

第 16 章到第 23 章不再按知识点展开，而是围绕开源系统建设展开。

这一部分的写法要遵守一个原则：

```text
先定义系统模块，
再写代码实验，
最后把实验整理成书稿。
```

也就是说，章节内容必须来自系统，而不是为了写章节而找概念。

## 第三部分目标

第三部分完成后，项目应该从“书稿 + Notebook”升级为“最小开源研究系统”。

读者应该可以完成一条最小研究流程：

```text
获取数据
→ 清洗和标准化
→ 计算指标
→ 生成策略信号
→ 执行回测
→ 计算风险指标
→ 输出报告
→ 记录复盘
```

这条流程暂时只做研究、回测和模拟盘，不做真实资金自动交易。

## [第 17 章：CEX 行情数据模块](17-cex-market-data-module.md)

状态：书面稿已完成。

系统模块：

```text
apps/collector/
src/quant_web3/data/
apps/api/app/models/
apps/api/app/api/routes/market.py
apps/web/src/pages/DataPage.tsx
```

本章要解决的问题：

- 如何结合 WebSocket 与 CCXT REST 持续获取闭合 K 线。
- 如何处理交易所 symbol、周期、UTC 边界、分页和限流。
- 如何通过唯一键、采集检查点和缺口扫描补齐数据。
- 逐笔成交与订单簿为什么不能照搬 K 线补数方式。
- 为什么连接正常不等于每个周期的数据完整。

最小实验：

```text
同时订阅 Binance、OKX 的 BTC/USDT 七种 K 线周期。
首次启动补齐历史数据，断线和定时巡检自动修复缺口。
查询记录数、最新闭合时间并检查一分钟数据连续性。
```

本章输出：

```text
原生 WebSocket 实时订阅
CCXT REST 初始化与补数
MySQL 幂等写入与采集检查点
CEX K 线、成交和订单簿字段说明
数据完整性检查与真实异常案例
```

## 第三部分完成标准

第三部分完成后，项目至少应该具备：

- 一个清晰的开源项目目录。
- 一个可运行的 CEX 行情数据获取示例。
- 一个可运行的链上交易读取示例。
- 一个指标计算模块。
- 一个配置化策略模块。
- 一个回测引擎。
- 一个回测报告输出。
- 一个最小模拟盘。
- 一个风险检查模块。
- 一个开源 README 初稿。

此时项目可以发布 V0.2。

## 当前开发顺序

建议按这个顺序推进：

```text
第 16 章：先整理目录和 README
第 17 章：整理 CEX 数据模块
第 19 章：整理指标模块
第 20 章：整理策略模块
第 21 章：整理回测模块
第 23 章：生成回测报告和开源发布清单
第 18 章：补链上数据模块
第 22 章：补模拟盘
```

原因很简单：当前已有 BTC 行情、指标、策略和回测 Notebook，先把已有内容系统化，成本最低。
